# AGENTS.md — DS Note Connector

Bridge between AI agents and Synology Note Station. Read `README.md` first;
`docs/API.md` is the API reference and `docs/VERIFIED.md` is the honest ledger
of what has actually been tested.

## Rules for this repository

1. **Never claim a DSM behaviour is verified unless it was observed.** The
   Note Station API is reverse-engineered. A claim is one of: capture (seen in
   real traffic, ours or a cited source), derived, guess, or verified by us.
   Anything unobserved goes in `docs/VERIFIED.md` as unverified.
2. **Pin API versions per method.** Never use the server's advertised
   `maxVersion` for a call — `SYNO.NoteStation.Note` advertises 4 while every
   captured `list` is v3 with a different parameter shape.
3. **Do not guess DSM error codes.** If a code is not in `core/errors.mjs`,
   report it as undocumented. Conflict detection works by re-reading and
   comparing `ver`, not by pattern-matching a number.
4. **Writes carry `ver` and `check_conflict=true`.** No exceptions.
5. **Trash and purge stay separate functions.** `purge` is gated behind
   `allowPurge`. Do not add a "just delete it" convenience path.
6. **Emit only HTML Note Station preserves.** The vocabulary is in
   `docs/API.md`; `<pre>`, `<code>`, `<blockquote>`, `<strong>`, `<em>` are
   excluded on purpose. `checkRoundTrip()` exists to check before writing.
7. **The fake NAS must keep failing the same way the real one does** — wrong
   path, bare params, missing CSRF token, stale `ver`. Do not relax it to make
   a test pass.
8. **No dependencies.** `node:` built-ins only, so the same core runs in a
   Cindy plugin, an MCP stdio server and on a NAS in Docker.

## Commands

```bash
npm test                        # 89 checks, node:test
node --check core/*.mjs         # syntax
node tests/fake-nas.mjs 8088    # fake NAS for manual poking
node tools/probe.mjs --help     # live verification (needs a real NAS)
node tools/sync-core.mjs        # vendor core/ into plugin/node/core
node tools/gen-manifest.mjs     # regenerate plugin/ghost.json tools
```

## Layout

- `core/` — the only implementation. Adapters must not reimplement it.
- `core/tools.mjs` — the tool catalog; every adapter exposes this, none adds behaviour.
- `variants/mcp/` — MCP stdio adapter.
- `plugin/` — native Cindy plugin. `plugin/node/core/` is a vendored copy; never edit it by hand, run `tools/sync-core.mjs`.
- `plugin/ghost.json` — the `tools` array is generated by `tools/gen-manifest.mjs`; never hand-edit it.
- `tools/` — fake NAS, live probe, and the two generators.
- `tests/` — one file per concern, all against the fake NAS or pure functions.

## Secrets

Never commit a NAS address, account, password, OTP seed or device token.
`DS_NOTE_PASSWORD`, `DS_NOTE_OTP` and `DS_NOTE_DEVICE_ID` are read from the
environment; logs redact `passwd`, `otp_code`, `_sid` and `synotoken`.

## Git

Commit and push are separate approvals. Present the proposed message, the
changed files and the test result, then wait.
