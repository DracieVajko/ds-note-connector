Each is probed with the certificate settings below; the first that answers wins. If none do, the QuickConnect ID is used.

Certificate and connection security

DSM accepts the code once, then remembers this device; the plugin clears it after a successful connection.

Making this harder to attack
  • A DSM user whose only permission is Note Station, with a password used nowhere else.
  • Two-factor on that account. The plugin never asks for the code again on a trusted device.
  • Verify the certificate — by name or by file — so the plugin trusts one certificate, not whatever answers on that address.
  • QuickConnect relay traffic passes through Synology and cannot be certificate-verified. A LAN or VPN route keeps the exchange between you and the NAS.

The password itself has to reach the local worker at login — DSM has no app-specific password or OAuth for third-party clients. The worker keeps it in memory only, hands it to no one, and the agent never sees it.
